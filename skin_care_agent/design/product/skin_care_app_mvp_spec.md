## 二、MVP 要验证的产品判断

### 1. 核心判断

用户愿意用较低负担记录自己当前在意的一个或多个面部区域、真实使用过的外用产品和后续状态。系统把这些记录整理成可追溯的个人历史后，用户能理解：

- 当时关注哪里；
- 当时记录到什么；
- 后来实际使用了什么；
- 同一区域随后怎样变化；
- 过去记录对当前有多少参考价值。

### 2. MVP 核心价值

MVP 用区域变化事件组织记录。一段事件连接同一区域的多个时间点，每个时间点可以包含照片、用户状态和个人感受。一次记录可以为多个用户主动选择的区域分别生成时间点，各区域独立积累趋势。

趋势本身只描述同一区域的可见状态怎样随时间变化。实际产品使用和生活背景只作为时间上下文展示，不参与阶段方向计算。用户本次没有记录某个区域时，该区域时间线只保留空档，系统不补齐、不推测，也不因此中断原有事件。

AI 负责减少填写，对用户已选区域进行可量化的外观观察，判断照片可比性并归纳跨时间变化。产品不输出诊断、治疗方案、产品推荐或皮肤评分。

### 3. MVP 完成标准

只有同时满足以下结果，MVP 才算形成完整产品闭环：

1. 用户可以用一张照片或无照片方式保存一个或多个当前关注区域；
2. 系统可以把各区域的后续记录分别续接到对应区域事件；
3. 用户可以独立记录已经发生的产品使用；
4. 用户可以沿同一区域的时间顺序回看状态、使用和生活背景；
5. 两个有效时间点可以形成前后变化，至少三个有效时间点且跨度不少于 7 天才形成阶段趋势；
6. 用户可以理解产品使用和生活背景只是时间上下文，不代表关联、疗效或因果。

## 三、版本边界

### 1. 本期必须提供

| 能力 | MVP 要求 |
|---|---|
| 账号与协议 | 邮箱密码、登录状态、总协议、隐私政策、账号注销 |
| 观察首页 | 一个皮肤变化主入口，一个独立产品使用快捷入口，轻量生活背景次卡 |
| 当前变化记录 | 默认拍一张照片，也可以在同一流程中跳过照片 |
| 关注区域 | 用户从固定面部区域中选择一个或多个本次想观察的区域，AI 只分析已选区域 |
| 照片处理 | 检查文件、清晰度、光线、人脸和区域可见性，保留原图并生成几何标准化副本 |
| 照片分析 | 按已选区域输出可见变化的估算数量、空间分布、覆盖范围、主要位置和日常外观，不生成医学分类或严重度 |
| 无照片与降级 | 无照片、照片不可比或 AI 不可用时，用户仍能用结构化状态完成记录 |
| 这次变化卡 | 可靠保存后展示本次事实、依据来源、已知信息和未知信息 |
| 区域事件 | 每个已选区域自动新建或续接对应事件，存在归属不确定时只显示一次分组确认 |
| 实际产品使用 | 记录已经发生的单个产品或组合使用，允许区域留空 |
| 观察提醒 | 用户主动选择一次性回看时间，不设置默认周期 |
| 历程与事件详情 | 按区域时间线回顾状态、原始依据、前后变化、阶段趋势和同时段上下文，不生成皮肤分数曲线 |
| 个人产品柜 | 从小型核心产品库选择，未收录产品可用名称建立临时条目 |
| 时间上下文 | 在事件详情中按真实发生时间展示产品使用和已记录的生活背景，不计算相关性 |
| 数据控制 | 照片授权、AI 授权、撤回、记录删除、照片删除、数据导出和账号注销 |

### 2. 本期保留但不作为主线

- 用户可以用贴纸补充睡眠、压力、饮食、情绪、生理期和护理变化；
- 用户可以记录“今天没有特别变化”，为以后留下平稳状态参照；
- MVP 只保存和回顾生活背景，不生成跨日生活线索；
- 产品库先覆盖高频核心产品，未收录产品不阻塞使用记录；
- 有足够同区域历史时才显示阶段趋势，冷启动不使用虚构内容填充页面。

### 3. 本期明确不做

- 正面、左侧、右侧三视角记录；
- 三视角介绍、自动推进、完整度检查和周期提醒；
- 全脸阶段趋势；
- 从相册批量导入旧照片；
- 自动扫描相册寻找历史；
- 包装照片识别和 OCR 产品建档；
- 使用图像特征进行相似历史排序；
- 单颗痘痘身份和生命周期追踪；
- 综合皮肤指数、严重度等级、改善分数或红绿输赢；
- 开放式 AI 问答、聊天或陪伴入口；
- 个体化产品推荐、用药建议、剂量、频次、疗程和组合建议；
- 产品排行榜、社区、内容流、电商和导购；
- 自动用药计划和疗程提醒；
- 跨日生活线索计算；
- 产品使用或生活背景的关联度、相关性、疗效和因果推断；
- 跨事件产品反应记忆和“形成个人规律”结论；
- 连续打卡、断签、任务完成率和焦虑提醒；
- 应用内复杂照片编辑、美颜、修复或生成式修改；
- 在上线前覆盖全部市场产品。

### 4. 后续能力的进入条件

团队不因长期产品文档存在某项能力就自动排期。后续能力需要真实用户证据：

- 三视角：用户需要全脸阶段资料，或单张照片长期无法覆盖目标区域；
- 包装识别：手动搜索和临时产品造成明显流失；
- 图像相似度：结构化区域和状态筛选无法提供有用历史；
- 跨日生活线索：用户积累了足够变化日与平稳日记录，并能理解关联边界；
- 产品反应记忆：用户已经积累足够多段独立事件，且单纯按时间回看无法满足复盘需求；
- 单颗追踪：区域事件无法回答用户问题，且标准化拍摄能提供稳定身份匹配。

## 四、核心记录模型

### 1. 区域变化事件

区域变化事件表示用户对一个面部区域的一段持续观察。事件不等于疾病、医学病程或单颗痘痘。

同一区域有正在观察的事件时，新记录默认续接。没有匹配事件时，系统建立新事件。连续 30 天没有新增记录时，事件转为“暂停追踪”。暂停只用于收纳，不表示痊愈、结束或失败。

用户可以在不同日期关注不同区域。切换关注区域不会结束、重置或污染其他区域的事件；同一区域下次被选择时继续进入原有时间线。连续性表示系统只比较同一区域，不要求用户每天记录，也不要求每次选择完全相同的区域组合。

### 2. 事件时间点

一次记录可以形成一个或多个事件时间点，每个已选区域形成一个时间点。同一次记录产生的时间点共用拍摄时间和原始照片，各自进入对应区域事件。时间点至少包含：

- 发生时间；
- 面部区域；
- 当前状态；
- 信息来源。

照片和个人感受是可选信息。照片分析、用户补充和无照片自述进入同一种时间点，不产生两套趋势。同一区域在一次记录中只生成一个时间点。

有效时间点必须已经可靠保存时间、区域、当前状态和至少一种状态依据。只有产品使用或生活背景、没有区域当前状态的记录不算趋势时间点。

### 3. 一张照片和多个关注区域

MVP 每次记录默认拍摄一张照片。用户从额头、鼻周、左脸颊、右脸颊、左太阳穴、右太阳穴、口周、下巴或下颌等固定面部区域中选择一个或多个本次想观察的区域。用户不需要区分主要区域和次要区域，也不需要绘制复杂范围。

系统必须保存完整原图，并将区域选择作为独立结构化数据保存。系统不能裁掉原图或修改皮肤像素。

AI 只分析和展示用户主动选择的区域。系统可以使用全脸轮廓和关键点完成区域定位、拍摄质量检查与几何对齐，但不能主动罗列未选择区域的皮肤问题。未选择某个区域只表示本次没有观察该区域，不表示该区域没有变化或状态稳定。

下次记录时，页面提供上次关注区域的快捷选项，用户可以沿用、增加或移除。系统不会在用户确认前分析这些区域。系统使用区域、视角、面部关键点、距离和光线信息判断照片是否可比；用户不需要确认是不是同一颗痘痘。

### 4. 时间上下文

实际产品使用和生活背景与区域状态分开保存：

- 生活背景按日期展示在当天的时间点详情中；
- 产品使用按真实发生时间展示在相邻时间点或两次观察之间；
- 用户填写了使用区域时，只在相应区域事件中展示；区域留空时，作为当时的全局背景展示；
- 上下文不改变时间点状态，也不参与“整体缓和”“更明显”等方向计算。

用户点击时间点可以查看当天已经记录的上下文，查看两个时间点之间的历程时可以看到期间发生的产品使用。系统只排列事实，不自动筛选“相关因素”，不输出关联强弱或因果解释。

### 5. 信息来源

每条状态事实必须标明来源：

- 照片分析；
- 用户记录；
- 照片与用户记录共同支持。

用户输入具有独立事实地位。AI 不得覆盖、降低或改写用户记录。

## 五、核心闭环

### 1. 第一次记录

用户在首页选择“记录现在的变化”
→ 默认进入拍摄
→ 用户可以选择“暂时不拍，直接记录”
→ 有照片时，系统检查拍摄质量
→ 用户选择一个或多个本次想观察的固定面部区域
→ AI 按区域整理估算数量、空间分布、覆盖范围、主要位置和可见外观
→ 照片无法补全信息或没有照片时，用户为已选区域补充当前状态
→ 系统可靠保存原始记录
→ 系统为各区域新建或续接对应区域事件
→ 页面生成“这次变化卡”
→ 用户可以结束，也可以补充产品使用或设置一次性提醒

第一次记录完成后，系统只整理当前事实。页面不展示趋势、相似历史、产品规律或通用建议。

### 2. 后续记录

用户再次记录皮肤变化
→ 系统提供角度、距离和光线提示
→ 用户拍一张照片或直接记录
→ 页面提供上次关注区域的快捷选项，用户可以沿用或重新选择
→ 系统分别判断各已选区域的照片可比性
→ 系统只让用户补充照片无法确认的信息
→ 各区域的新时间点分别续接到对应区域事件
→ 有两个有效时间点时，系统可以生成该区域的前后变化
→ 至少有三个有效时间点且跨度不少于 7 天时，系统才生成该区域的阶段趋势

某个区域的照片不可比时，系统停止该区域的照片比较。用户记录的当前状态仍进入对应区域趋势。

### 3. 实际产品使用

用户通过首页快捷入口、变化卡或事件详情选择“记录刚刚使用”
→ 选择个人产品或组合
→ 确认真实使用时间
→ 可选填写区域和个人感受
→ 系统保存使用事实

使用记录可以脱离变化事件独立存在。系统只按真实时间和用户填写的区域把它展示在相应历程中，不能用使用记录自动新建区域事件，也不能生成关联、疗效或因果结论。

### 4. 历程中的上下文

事件详情以区域状态时间线为主体。用户打开某个时间点时，可以查看当天已经记录的个人感受和生活背景；查看两个时间点之间时，可以看到期间发生的产品使用。

上下文与皮肤状态并列展示，不作为趋势的一部分。系统不选择“最相关因素”，不汇总产品反应方向，也不形成个人规律。组合使用仍按真实使用事实保存，不把组合后的状态变化归给其中一个产品。

## 六、信息架构

一级导航固定为：

- 观察；
- 历程；
- 产品；
- 我的。

MVP 不设置 AI、问答、陪伴或内容入口。

### 1. 观察

观察首页只保留一个皮肤变化主入口。

页面顺序固定：

1. 核心承诺；
2. “记录皮肤变化”主卡；
3. “记录刚刚使用”独立快捷入口；
4. “今天的生活背景”轻量次卡；
5. 用户主动设置的一次性回看提示。

主卡包含：

- 标题“记录皮肤变化”；
- 说明“选择这次想观察的区域，留住当前变化”；
- 唯一主要按钮“记录现在的变化”；
- 辅助说明“进入后可以拍照，也可以直接记录”。

首页不出现三视角、完整记录或并列手动记录入口。“记录刚刚使用”不放在拍照主卡内。

### 2. 历程

历程按区域变化事件展示：

- 区域和开始日期；
- 正在观察、暂停追踪或停止记录；
- 时间点数量；
- 当前前后变化、阶段趋势或证据不足说明；
- 结论依据来源。

列表默认遮盖真实照片。用户进入事件详情后，可以主动查看原始依据。

事件详情使用按时间排列的时间线，不使用综合皮肤分数作为纵轴，也不强制绘制连续折线。每个时间点展示当时的区域状态和依据；点击后展开照片、用户记录、个人感受和当天生活背景。两个时间点之间可以展示期间发生的产品使用。

某段时间没有记录时，时间线上保留自然空档，不连接成系统推测的连续变化。阶段趋势只概括已有有效时间点。

### 3. 产品

产品页包含：

- 小型核心产品库搜索；
- 个人产品柜；
- 临时产品添加；
- 已发生的使用记录；
- 按时间查看某个产品或组合的实际使用历史。

产品页不展示推荐榜、疗程、购买入口或通用产品评价。

### 4. 我的

我的页面包含：

- 观察提醒和记录偏好；
- 照片预览与 AI 授权；
- 存储、导出和删除；
- 账号与安全；
- 产品能力边界、隐私说明和反馈。

## 七、必要页面

| 页面 | 主要任务 | MVP 关键状态 |
|---|---|---|
| 开屏协议 | 同意协议并进入产品 | 同意、拒绝、查看全文 |
| 注册与登录 | 建立个人数据空间 | 正常、验证失败、网络失败 |
| 观察首页 | 发起变化记录或产品使用 | 首次、有历史、有主动提醒 |
| 拍摄页 | 拍一张当前照片 | 相机授权、可拍、建议调整、文件失败 |
| 关注区域选择 | 选择一个或多个固定面部区域 | 首次选择、沿用上次、增加、移除 |
| 无照片状态记录 | 选择一个或多个区域、当前状态和可选感受 | 正常、AI 不可用、区域未确定 |
| 保存状态 | 可靠持久化原始记录 | 保存中、保存失败、已保存 |
| 这次变化卡 | 解释本次事实和信息边界 | 有可比照片、照片不可比、无照片 |
| 产品使用记录 | 保存单品或组合的真实使用 | 有个人产品、临时产品、区域留空 |
| 提醒选择 | 设置一次性回看 | 明天、3 天后、7 天后、自定义、不提醒 |
| 历程 | 浏览区域事件 | 空状态、正在观察、暂停追踪 |
| 事件详情 | 查看区域时间线、前后变化、阶段趋势、原始依据和时间上下文 | 基线、仅可前后比较、有阶段趋势、数据被删除后重算 |
| 产品柜 | 管理个人产品 | 核心产品、临时产品、组合 |
| 产品详情 | 查看产品信息和实际使用历史 | 尚无使用记录、有单品记录、有组合记录 |
| 我的 | 管理权限和数据 | 授权开启、授权撤回、删除、导出 |

## 八、记录与反馈规则

### 1. 拍摄引导

拍摄页只提示对后续比较有直接作用的信息：

- 让关注区域清晰可见；
- 保持光线均匀；
- 保持面部角度和距离稳定；
- 避免遮挡。

轻微偏差只触发可跳过建议。文件损坏、目标区域不可见、严重模糊或明显过曝欠曝时，系统说明原因并允许重拍。用户仍可跳过照片并完成状态记录。

### 2. 关注区域

用户至少选择一个固定面部区域，可以同时选择多个。界面应说明：

“选择这次想观察的区域，可多选。我们只分析你选择的区域，并按区域分别积累记录。”

页面可以提供上次关注区域作为快捷选项，但必须由用户确认。用户不需要使用专业皮损名称，也不需要区分区域的主次。AI 不可用时，固定区域选择仍可正常使用。

### 3. 这次变化卡

保存完成后，页面先显示“这次记录已保存”。卡片按以下顺序组织：

1. 我注意到的；
2. 照片留下的事实；
3. 目前知道的；
4. 目前还不知道的。

卡片至少显示记录时间、已选区域、照片依据、各区域的可比性和信息来源。用户选择多个区域时，卡片按区域分组展示本次事实，不生成全脸综合评分或跨区域变化结论。

照片满足分析条件时，每个区域默认展示估算数量、分布形态和一项主要可见外观，最多显示三项。系统保存完整结构化结果供后续比较；页面不把数量放大为评分或好坏评价。

卡片生成代表本次记录已经完整。产品使用、生活背景和提醒都属于可选补充，页面不能显示未完成状态。

### 4. 保存语义

只有原始照片或无照片状态、区域、时间和用户事实完成可靠持久化后，界面才能提示“已保存”。

页面必须区分：

- 仍在上传；
- AI 正在整理；
- 原始记录已保存但派生结果失败；
- 保存失败；
- 保存完成。

AI 失败不能撤销已经保存的原始记录。

## 九、证据与结论

### 1. 三类信息

MVP 分开保存和展示：

1. 原始证据：原始照片、用户状态、个人感受、时间、区域和信息来源；
2. 变化摘要：同一区域多个时间点的中性整理；
3. 时间上下文：产品使用和生活背景按真实发生时间排列。

只有原始证据和同区域状态变化用于生成前后变化与阶段趋势。时间上下文只供用户回看，不参与趋势方向计算。系统可以重新生成变化摘要，不能覆盖原始照片或改写用户输入。

### 2. 照片可比性

可比性决定系统能否生成照片比较结论，不决定一条记录能否进入个人趋势。

系统按区域分别判断可比性。同一张照片中的不同区域可以得到不同的可比性结果。

照片比较至少检查：

- 面部区域一致；
- 视角和头部姿态接近；
- 距离和区域占比接近；
- 光线与曝光没有明显偏差；
- 关注区域清晰且无遮挡；
- 几何对齐可用。

系统只有获得同一区域两张可比较照片后，才能描述照片中的跨时间变化。

### 3. 前后变化与阶段趋势门槛

同一区域只有一个有效时间点时，系统只展示当前事实并将其作为基线。

同一区域有两个有效时间点时，系统可以描述本次相对上次的“前后变化”，但不能称为阶段趋势。照片维度的前后变化还要求至少两张可比较照片；照片不可比时，只能依据用户状态描述可支持的变化，并标明来源。

同一区域至少有三个有效时间点，且最早与最晚时间跨度不少于 7 天时，系统才生成阶段趋势。阶段趋势综合已有时间点，不把缺失日期补成稳定、缓和或更明显。

前后变化与阶段趋势只能使用：

- 整体缓和；
- 更明显；
- 基本稳定；
- 变化混合；
- 信息不足。

系统同时展示支持结论的变化维度和信息来源。变化维度可以包括估算数量、覆盖范围、分布形态、泛红范围、凸起与表面状态和平坦色印；这些维度不合成为综合分数，页面不显示置信度分数。

### 4. 阶段趋势展示

事件详情在证据允许时使用以下结构：

1. 当前变化：说明前后变化、阶段趋势或信息不足；
2. 判断依据：列出有效时间点、时间跨度、信息来源和具体变化维度；
3. 数据边界：说明不可比照片、缺失日期、来源差异和矛盾证据；
4. 下一步：只建议继续观察、补全信息、回顾原始依据或准备专业咨询。

第四段不能变成购买、再次使用、停用、更换、组合、剂量、频次或疗程建议。

### 5. 缺失信息

系统按以下语义处理缺失：

- 未记录不等于没有发生；
- 未记录产品不等于没有使用；
- 没有后续记录不等于痊愈、恶化或放弃；
- 暂停追踪不等于事件结束；
- 没有照片不等于没有变化；
- 照片不可比不等于本次记录无效；
- 无法可靠计数不等于没有可见变化。

## 十、AI 能力边界

### 1. MVP 使用 AI 的位置

AI 可以：

- 对用户已选区域进行可量化的外观观察；
- 判断已选区域是否清晰可见；
- 分别判断各已选区域是否具备比较条件；
- 将用户状态整理为结构化事实；
- 为各已选区域新建或续接对应事件，存在归属不确定时请求一次分组确认；
- 综合多个时间点生成带依据的前后变化或阶段趋势；
- 按固定结构生成前后变化和阶段趋势说明；
- 选择一个必要的结构化追问；
- 在固定结构内生成克制文案。

### 2. 单次照片结构化分析

系统为每个已选区域生成一份独立结果。结果包含估算数量、空间分布和可见外观。

#### 数量估算

数量字段使用以下状态：

- 未见明确点状变化；
- 约 N 处；
- 约 N 至 M 处；
- 无法可靠计数。

可见变化数量较少且边界清楚时，AI 输出约数。数量较多、互相遮挡或连片时，AI 输出区间。照片模糊、过曝、欠曝或区域被遮挡时，AI 不输出数量，并说明无法可靠计数。

#### 空间分布

空间分布由分布形态、覆盖范围和主要位置组成。数量与覆盖范围共同表达密集程度；分布形态只描述空间组织。

分布形态使用以下状态：

- 单处：只有一处独立可见变化；
- 零散分布：多处变化彼此分开，没有明显聚集中心；
- 单片集中：主要集中在一个局部范围；
- 多片集中：形成两个或多个相互分开的集中范围；
- 广泛散布：覆盖所选区域的多个位置，没有明显集中范围；
- 连片分布：多处变化相互邻近或重叠，难以逐个区分；
- 混合分布：同时存在集中区域和外围零散变化；
- 无法判断：照片质量或遮挡不足以支持判断。

覆盖范围使用“很局部”“局部”“较广”或“无法判断”。这些状态只描述变化在所选区域内占据的范围。

主要位置使用“中央”“上部”“下部”“靠内侧”“靠外侧”或“分散在多个位置”。系统无法稳定定位时不输出主要位置。

#### 可见外观

AI 可以使用以下日常外观描述：

- 泛红；
- 凸起；
- 带白色顶点；
- 平坦的红色印记；
- 平坦的褐色印记；
- 局部脱屑；
- 表面干燥；
- 局部反光明显；
- 多种外观同时存在；
- 当前照片无法可靠判断。

AI 可以为可区分的外观附加约数或数量区间，例如“约 3 处泛红凸起，其中 1 处带白色顶点”。

#### 展示与保存

- “这次变化卡”每个区域默认展示估算数量、分布形态和一项主要可见外观，最多三项；
- 系统将完整结构化结果作为可重算的派生数据保存，用于后续同区域比较；
- 系统不统计或展示全脸可见变化总数；
- 系统不把数量、覆盖范围或分布状态合成为分数或好坏等级；
- 任何字段缺少可靠依据时，系统返回“无法判断”，不使用其他字段推测补齐。

### 3. 跨时间照片比较

同一区域至少有两张可比较照片时，AI 可以比较：

- 估算数量：增加、减少、接近或无法判断；
- 覆盖范围：缩小、扩大、接近或无法判断；
- 分布形态：更集中、更分散、由零散变为连片、接近或变化混合；
- 泛红范围：缩小、扩大、接近或无法判断；
- 凸起和表面状态：更明显、较不明显、接近或无法判断；
- 平坦色印：增多、减少、接近或无法判断。

系统只比较区域层面的总体变化，不确认某一处可见变化的身份，也不生成单颗痘痘的新生、消退或痊愈结论。

### 4. MVP 禁止 AI 执行

AI 不得：

- 主动分析或展示用户未选择区域的皮肤问题；
- 统计或展示全脸可见变化总数；
- 诊断疾病或病因；
- 输出医学皮损分类；
- 判断严重程度或医疗风险等级；
- 推荐用户选择、开始、继续、停止或更换具体产品；
- 提供剂量、频次、疗程或联合使用建议；
- 把时间先后改写为疗效、过敏或其他因果；
- 计算或暗示产品使用、生活背景与皮肤变化的关联度；
- 使用通用护肤建议填补个人证据不足；
- 生成、修复、美化或修改用户皮肤照片；
- 与其他用户照片比较；
- 用模型结论覆盖用户记录。

### 5. AI 不可用

AI 不可用时，用户仍可以：

- 保存原始照片；
- 手动选择一个或多个固定区域；
- 选择当前状态；
- 记录个人感受；
- 保存产品使用；
- 设置一次性提醒；
- 查看已经保存的历史。

系统用固定结构生成基础“这次变化卡”，不能虚构照片观察、比较结果或个人规律。

## 十一、安全、隐私与用户控制

### 1. 分步授权

总协议和隐私政策是进入产品的前提。相机、照片保存和 AI 分析在用户第一次使用对应能力时单独授权。

用户拒绝照片或 AI 授权后，仍可进入产品、记录无照片状态、管理产品和查看历史。产品不反复弹出授权请求。

### 2. 照片真实性

系统保持原始照片不可变。几何标准化和隐私遮挡使用独立副本，区域选择使用结构化数据或展示层。任何处理都不能改变皮肤像素语义。

首页、提醒和历程列表默认遮盖真实照片。用户主动选择查看依据并确认后，页面才显示原图。

### 3. 删除与重算

用户可以删除照片、单条记录、事件或账号。

删除照片时，系统同步删除由该照片生成的图像特征、可见事实和照片比较结果。用户独立填写的状态、产品使用和个人感受可以按用户选择保留。

删除记录后，系统立即使引用该记录的前后变化和阶段趋势失效，并按剩余证据重新计算。按时间展示的产品使用和生活背景只在对应原始记录仍存在时保留。

### 4. 输出安全

正常的个人结论和记录建议不重复展示长篇免责文案。

用户要求诊断、治疗、具体用药决策或医疗风险判断时，页面显示：

“本产品只保存和整理个人记录，不能判断病情、诊断原因或提供治疗建议；如对当前情况感到担心，请咨询具备资质的医疗专业人员；如认为情况紧急，请联系当地急救服务。”

系统随后停止越界分析，但允许用户保存原始记录。

副标题：

首页不突出 AI。

页面使用“变化”“这次记录”“当前区域”“正在观察的下巴区域”等自然表达。页面不要求用户理解事件、趋势点、派生结果等内部术语。

文案不评价皮肤好坏，不评价用户是否自律，不使用羞耻、恐吓、失败暗示或灾难化语言。

### 3. 视觉层级

## 十三、MVP 验收

### 1. 核心流程

- 用户可以从首页用一个主入口开始记录；
- 用户可以拍一张照片，也可以在同一流程中跳过照片；
- 用户可以选择一个或多个固定面部区域，不需要绘制复杂范围；
- AI 只分析和展示用户确认的区域；
- 照片满足条件时，AI 可以按区域输出估算数量、空间分布、覆盖范围、主要位置和可见外观；
- 同一区域照片满足可比条件时，AI 可以比较数量、范围、分布和外观变化；
- 数量较多、连片或照片质量不足时，AI 使用区间或“无法可靠计数”，不强行输出精确数字；
- 照片不可比和 AI 失败都不会阻塞基础记录；
- 系统在可靠保存后生成“这次变化卡”；
- 用户可以记录实际产品使用，并在区域历程中按真实时间回看；
- 用户可以从历程进入同一区域事件，沿时间顺序查看区域状态及同时段上下文；
- 一个时间点只建立基线，两个有效时间点只形成前后变化，至少三个有效时间点且跨度不少于 7 天才形成阶段趋势；
- 页面不把多个外观维度合成为综合分数或连续皮肤曲线；
- 产品使用和生活背景不参与趋势方向计算，页面不输出关联强弱；
- 证据达到门槛后，页面能展示结论、依据、数据边界和下一步；
- 用户可以删除原始记录，相关派生结果随之失效。

### 2. 产品理解

可用性测试需要确认：

- 用户能否理解首页只有一个皮肤变化入口；
- 用户能否理解拍照和直接记录属于同一流程；
- 用户能否理解一次照片可以记录多个区域，各区域独立积累趋势；
- 用户能否理解更换本次关注区域不会结束或污染其他区域的历史；
- 用户能否理解未选择区域表示本次没有观察，系统不会据此判断该区域状态；
- 用户能否理解数量是 AI 对可见外观的估算，不是医学皮损计数；
- 用户能否理解分布和覆盖范围描述所选区域中的外观，不代表医学严重程度；
- 用户能否区分照片事实、用户记录和综合结论；
- 用户能否理解产品使用和生活背景只是时间上下文，不代表相关性或疗效；
- 用户是否把产品误认为诊断或产品推荐工具。

### 3. 发布阻断项

以下问题未解决时，MVP 不进入公开测试：

- 原始记录可能在页面提示成功后丢失；
- 账号之间可以读取彼此记录；
- 原始照片会被生成式修改；
- 无照片或 AI 失败时无法完成记录；
- 页面输出诊断、治疗或产品推荐；
- AI 主动展示用户未选择区域的皮肤问题；
- AI 在照片不具备计数条件时强行输出精确数量；
- AI 把日常外观描述改写为医学皮损分类或严重度等级；
- 页面把产品使用或生活背景纳入趋势方向，或者暗示其与变化存在关联；
- 删除照片后仍保留由照片生成的派生结果；
- 三视角旧流程仍是新记录的必填条件；
- 首页仍出现多个含义接近的拍照入口。

## 十四、与现有实现的关系

现有代码中的标准 Check-in、正面与左右侧三张必拍、综合皮肤指数、按日趋势和开放式 AI 问答均不定义 MVP。

改造时遵守以下产品结果：

- 一次记录允许零张或一张照片完成；
- 数据模型允许未来关联多张照片，但接口不能要求三视角齐全；
- 用户选择的固定面部区域作为结构化数据独立保存；
- 一条记录可以形成一个或多个区域时间点，每个已选区域最多一个；
- 同一次记录的区域时间点共用原始照片、拍摄时间和拍摄条件；
- 单次照片分析按区域保存估算数量、分布形态、覆盖范围、主要位置和可见外观，所有字段允许“无法判断”；
- 跨时间照片比较按区域保存各维度的变化方向，不保存单颗痘痘身份；
- 趋势计算只读取同一区域的有效状态时间点，不读取产品使用或生活背景作为方向依据；
- 一个有效时间点只建立基线，两个时间点只允许前后比较，至少三个有效时间点且跨度不少于 7 天才允许生成阶段趋势；
- 事件详情按时间展示状态点和上下文，不依赖综合皮肤分数或连续折线；
- 首页只有一个皮肤变化主入口；
- 旧三视角页面不进入新导航和新记录流程；
- 旧数据保留并做降级映射，不能伪装成符合新规则的可比证据。

具体数据库、API、迁移和客户端任务由实施计划定义。本文件不绑定服务类、路由名称或表结构。

## 十五、开发取舍顺序

开发进度或资源不足时，按以下顺序保护范围：

1. 可靠保存照片或无照片状态；
2. 一个或多个用户主动选择的固定面部区域，以及各区域独立的事件时间点；
3. 这次变化卡；
4. 后续记录续接和事件回顾；
5. 实际产品使用；
6. 前后变化、阶段趋势和同时段产品使用展示；
7. 生活背景展示、临时产品体验和其他次级优化。

团队可以推迟第七项中的体验优化，不能用它们替代前六项。

## 十六、变更规则

新增能力进入 MVP 前，需要回答：

1. 它是否直接帮助用户完成“当时状态、实际使用、后来怎样”的闭环；
2. 删除它是否会导致核心价值无法验证；
3. 它是否增加新的权限、数据模型、核心页面或 AI 结论；
4. 团队能否在当前版本内完成实现和验证。

第二项答案为“否”且第三项答案为“是”时，该能力移入后续版本。

# Skin Care App MVP 产品规格

> 文档状态：ACTIVE，当前开发与验收的唯一产品事实源。
>
> 更新日期：2026-08-21。
>
> 职责：定义当前 MVP 的唯一产品范围、行为、数据语义、AI 边界、切片顺序和发布门槛。

## 1. 文档职责与优先级

本文件是当前 MVP 的唯一产品事实源。实施计划只能细化这里已经确认的要求，不能自行增加产品范围。`docs/current_status.md` 只记录经代码、测试、迁移或 Git 验证的事实，不能替代产品定义。

早期设想、第二版完整设计、旧三视角原型和旧迁移计划均为历史资料。需要追溯时查看 Git 历史或外部备份，不得据此恢复本文件未包含的功能。

本版已确认两项界面和范围决策：

- 底部导航采用四栏：观察、历程、产品、我的；
- 首版不建设平台总产品池，只提供个人产品柜、手动录入和“未注明产品”。

当前 ACTIVE 实施计划由 `docs/current_status.md` 指定；计划只能细化本文件。

## 2. MVP 要验证的判断

MVP 首先验证一个最小行为闭环：用户是否愿意拍摄一张全脸照片，让系统整理中性的可见状态，再记录一次真实发生的产品使用，并在之后回来查看这些事实。

完整 MVP 进一步验证：当用户积累多个时间点后，按时间排列的原始记录、可追溯的前后变化和阶段趋势，是否比单次拍照结果更有长期价值。

首版不以“按区域追踪”为成立前提。区域选择、区域事件和区域趋势属于后续扩展，不能阻塞全脸闭环上线。

## 3. 产品原则

### 3.1 原始记录优先

系统先可靠保存原始照片、记录发生时间和用户原文，再启动 AI。AI 结果是可重新生成的派生数据，不能覆盖或修改原始记录。

### 3.2 全脸是观察范围，不是一个面部区域

领域模型使用通用 `observation_scope`：

- 当前 MVP 固定为 `full_face`；
- 当前界面默认全脸，不展示只有一个选项的范围选择页；
- 后续可以增加 `region`，并让“全脸”和“选择区域”互斥；
- `full_face` 不作为第七个区域，不进入区域事件或区域趋势；
- 以后开放区域能力时，不把历史全脸结论伪装成区域证据。若保留了原图，可在用户授权和新模型规则下重新处理，结果另存版本。

### 3.3 观察、产品使用和生活背景分离

皮肤观察、实际产品使用、生活背景贴纸是三类独立事实。它们可以按时间并列展示，但产品使用和生活背景不参与变化方向计算，不生成相关性、疗效或因果结论。

### 3.4 中性、可追溯、可降级

AI 只整理照片能够支持的日常外观事实。每项派生结果必须保留来源、模型或提示版本、生成时间和证据引用。证据不足、AI 失败或引用校验失败时，系统展示固定降级说明，用户仍可用文字完成记录。

## 4. 当前 MVP 范围

### 4.1 必须提供

| 能力 | MVP 要求 |
|---|---|
| 账号与协议 | 邮箱密码、会话恢复、必要协议与照片/AI 授权 |
| 四栏导航 | 观察、历程、产品、我的 |
| 单张照片记录 | 拍摄一张可读取的照片并可靠保存原图与记录时间 |
| 无照片降级 | 用户可以跳过照片，用非空文字保存一次观察 |
| 全脸观察范围 | 当前自动使用 `full_face`，不展示范围选择页 |
| 异步 AI | 原始记录保存成功后异步处理；用户离开再返回仍能看到状态和结果 |
| 全脸状态事实 | 中性描述主要位置、估算数量或范围、分布、覆盖和日常外观；不支持的字段明确为无法判断 |
| 这次记录 | 展示原始依据、用户原文、AI 事实、已知信息、未知信息和处理状态 |
| 实际产品使用 | 记录一次真实发生的使用，可选多个个人产品，也可保存“未注明产品” |
| 个人产品柜 | 以名称保存用户自己的产品；找不到时可输入名称并立即加入个人产品柜 |
| 生活背景贴纸 | 在记录完成后选择固定字典贴纸或全部跳过，只作时间上下文 |
| 历程 | 按发生时间回看全脸观察、产品使用和生活背景 |
| 前后变化 | 两个有效全脸观察时间点时展示有证据引用的前后变化 |
| 阶段趋势 | 至少三个有效全脸观察时间点且跨度不少于 7 天时展示证据型阶段趋势 |
| 数据控制 | 授权状态、授权撤回、数据导出和账号隔离 |

### 4.2 明确不做

- 六个固定区域的选择、按区域 AI 评估、区域事件和区域趋势；
- 正面、左侧、右侧三视角必拍及拍摄完整度门槛；
- 平台总产品池、品牌/规格/浓度/包装资料补全；
- 包装识别、OCR、相册批量导入和自动扫描相册；
- 单颗痘痘身份和生命周期追踪；
- 医学诊断、医学皮损分类、严重度、治疗或用药建议；
- 综合皮肤分数、改善分数、连续评分曲线和红绿输赢表达；
- 产品推荐、排行榜、社区、内容流、电商和导购；
- 产品使用或生活背景的相关性、疗效和因果推断；
- 开放式 AI 聊天、连续打卡、提醒和任务完成率；
- 生成式修改、美颜或修复用户原始照片；
- 为了兼容旧实现而继续暴露旧三视角、旧医学分析或旧皮肤指数流程。

## 5. 信息架构

底部导航固定为四栏：

| 导航 | 主要职责 |
|---|---|
| 观察 | 发起一次全脸观察，查看最近记录，并提供“记录产品使用”快捷入口 |
| 历程 | 按时间回看观察、产品使用、生活背景、前后变化和阶段趋势 |
| 产品 | 管理个人产品柜并查看各产品的真实使用历史 |
| 我的 | 账号、协议、照片与 AI 授权、数据导出和设置 |

四栏都是一级页面。首版不额外增加独立“AI”“趋势”“聊天”或“打卡”一级入口。

## 6. 核心数据语义

### 6.1 ObservationRecord：原始观察记录

一次用户主动保存的观察。至少包含：

- 用户标识；
- 客户端幂等标识；
- 记录发生时间，后端按 UTC 保存并按设备当地时间显示；
- 零张或一张原始照片；
- 可选的用户状态原文；
- 原始记录保存状态；
- 创建和更新时间。

有照片时只校验文件能够正常读取，不设置清晰度、姿态、光照、美妆或三视角质量门槛。原图不可被 AI 或图像处理覆盖。照片元数据中的拍摄时间可以另存，但不覆盖记录发生时间。

无照片时，用户状态原文去除首尾空格后必须非空，最多 500 字。用户原文永久独立保存，AI 整理不能覆盖它。

### 6.2 ObservationTarget：观察目标

每条记录至少关联一个观察目标。当前 MVP 自动创建：

- `scope_type = full_face`；
- `region_id = null`；
- 独立的 AI 处理状态；
- 派生事实集合；
- 模型、提示和结果 Schema 版本。

数据模型可以容纳未来的 `scope_type = region`，但当前 API 和界面不能开放区域参数或区域选择。

### 6.3 状态机

原始记录保存与 AI 处理必须分开：

| 对象 | 状态 | 用户可见行为 |
|---|---|---|
| 原始记录 | `saving` | 显示正在保存，不得宣称成功 |
| 原始记录 | `saved` | 原图/原文和时间已可靠保存，可以离开页面 |
| 原始记录 | `save_failed` | 明确提示重试；不得创建 AI 任务 |
| 观察目标 | `queued` | 已进入 AI 队列 |
| 观察目标 | `processing` | 正在整理照片事实 |
| 观察目标 | `completed` | 结果已保存并通过展示校验 |
| 观察目标 | `needs_input` | 无照片、AI 最终失败或没有可用事实，提示用户补充文字 |

网关内部可以保存失败原因和重试次数，但前端不得把技术错误直接暴露给用户。迟到的 AI 结果不能覆盖已经提交的用户原文，也不能静默改变信息来源。

### 6.4 全脸 AI 事实

照片结果使用结构化字段，各字段均允许“无法判断”：

- `main_locations`：照片中可见变化主要出现的位置；
- `estimated_amount`：只在照片足以支持时给出近似数量或范围，不强行精确计数；
- `distribution`：例如集中、散在或无法判断；
- `coverage`：对全脸可见范围的中性描述；
- `daily_appearance`：颜色、表面和可见形态的日常语言描述；
- `unknowns`：照片无法支持的判断及原因；
- `summary`：不超过 200 字的中性概述。

这些字段描述照片中的可见外观，不是医学皮损、疾病类型或严重度。系统不能输出“痤疮等级”“炎症程度”“应使用某产品”等越界内容。

### 6.5 Product 与 ProductUse

个人产品至少保存用户内唯一标识、名称和创建时间。名称去除首尾空格后不能为空；首版不要求品牌、规格、浓度、包装图片或平台标准 ID。

一次实际使用记录至少包含：

- 用户标识；
- 真实使用时间，默认当前时间且允许修改；
- 零个或多个个人产品；
- 可选备注；
- 创建时间。

用户可以多选已有个人产品。输入一个新名称并确认后，系统先将其保存到个人产品柜，再关联到本次使用。用户也可以不选择产品，以“未注明产品”完成记录；它是无产品关联的显示语义，不创建一个伪产品实体。

产品使用不依附于某次照片记录才能成立，也不能被拆分或重写为产品疗效证据。

### 6.6 LifeContext：生活背景贴纸

固定字典首版包含：睡眠、压力、饮食、情绪、生理期、护理变化。用户可以多选或全部跳过。

贴纸关联到一次观察记录，保存稳定 ID，并按原始选择展示。贴纸不交给 AI 推断或改写，不参与前后变化和阶段趋势。

### 6.7 有效观察时间点

一条记录只有满足下列任一条件，才成为趋势可以引用的有效观察时间点：

- 全脸观察目标状态为 `completed`，且至少保存一项通过校验的 AI 状态事实；
- 用户提交了去除首尾空格后非空的状态原文。

只有照片、日期、产品使用或生活贴纸，但没有任何有效状态事实的记录，可以保留在历程中，但不能进入前后变化和阶段趋势。AI 处理中时也不能提前进入趋势计算。

### 6.8 派生比较与趋势

派生结果只读取有效的 `full_face` 观察事实：

- 一个有效时间点：只展示基线，不生成变化结论；
- 两个有效时间点：只生成前后变化；
- 至少三个有效时间点且首尾跨度不少于 7 天：可以生成阶段趋势。

每个结果至少保存：自然语言摘要、引用的时间点、引用的事实、信息来源、无法支持的部分、生成模型/提示/Schema 版本和生成时间。

趋势生成不读取产品使用或生活贴纸作为方向依据。不同来源的事实可以同时出现，但页面必须标注来源差异。照片不可比、日期缺失、字段无法判断、证据不足或引用校验失败时，不发布 AI 结论，只展示固定的数据边界说明。

## 7. 核心用户流程

### 7.1 全脸照片记录

用户在“观察”点击记录
→ 拍摄一张照片，或选择暂时不拍
→ 系统自动使用 `full_face`
→ 有照片时先上传并可靠保存原图与记录时间
→ 页面在确认 `saved` 后提示记录成功
→ 系统异步创建并处理观察目标
→ 用户可以离开页面
→ 再次进入“观察”或“历程”时看到排队中、处理中、已完成或需要补充文字
→ 结果完成后展示这次记录卡
→ 用户可以补充生活背景或发起产品使用记录。

### 7.2 无照片与 AI 降级

用户跳过照片时直接输入非空状态原文。AI 最终失败、照片没有任何可用事实或展示校验不通过时，原始记录仍然存在，目标进入 `needs_input`，用户可补充非空原文完成有效时间点。

技术失败不得导致原图丢失，也不得阻塞产品使用记录。

### 7.3 产品使用

用户从“观察”快捷入口、记录完成卡或“产品”页发起
→ 选择零个或多个个人产品
→ 找不到时输入名称并加入个人产品柜
→ 可修改真实使用时间并填写备注
→ 保存
→ 使用事实出现在历程和相应产品历史中。

### 7.4 历程与趋势

历程按真实发生时间展示全脸观察、产品使用和生活背景。用户打开观察记录时可以看到原始照片或原文、AI 事实、来源、处理状态和数据边界。

达到门槛后，页面逐步展示基线、前后变化或阶段趋势。产品使用和生活背景可以显示在相邻时间位置，但视觉和文案必须明确它们只是上下文。

## 8. 纵向切片

### 准备阶段：新旧边界与契约基础

目标是让后续切片可以在不沿用旧医学业务模型的前提下开发。

- 定义 `ObservationRecord`、`ObservationTarget`、处理状态、事实来源和版本字段；
- `observation_scope` 支持当前 `full_face` 和未来 `region` 的扩展形态；
- 新记录独立于旧三视角 CheckIn；
- 明确幂等保存、异步 AI 和重新读取契约；
- 复用认证、对象存储、签名 URL、通用 AI gateway 和 Expo 基础；
- 旧路由和旧页面暂不删除，但不进入新导航；
- 将主题色改为语义 token，并为新四栏壳层使用 MVP 配色；不重绘 legacy 页面。

准备阶段不算可交付产品切片，不能无限扩张为整体后端重写。

### 切片 1：单张全脸照片与异步 AI 降级闭环

用户能够：

- 拍摄一张可读取的照片，或跳过照片改用文字；
- 先可靠保存原图/原文和记录时间；
- 默认以 `full_face` 建立观察目标，不经过选择页；
- 离开页面后重新进入仍能看到处理状态和结果；
- AI 失败或无有效事实时保留原始记录并补充文字；
- 在历程中重新打开这次记录。

完成标准：真后端持久化、真实异步状态恢复和移动端流程通过自动化测试；静态 Mock 不算完成。

### 切片 2：实际产品使用与个人产品柜

用户能够：

- 独立记录一次真实发生的产品使用；
- 从个人产品柜选择一个或多个产品；
- 输入新名称并立即保存为个人产品；
- 不选择产品，以“未注明产品”完成；
- 修改真实使用时间并填写可选备注；
- 在历程和产品页回看使用事实。

完成切片 1–2 后，可以邀请小范围 Alpha 用户验证“拍照—AI 整理—产品记录”的最小闭环，但不视为公开测试就绪。

### 切片 3：重复记录、历程与生活背景

用户能够：

- 重复新增全脸照片或文字记录；
- 按时间查看原始记录、AI 事实、产品使用和来源；
- 在观察完成后添加固定生活背景贴纸或全部跳过；
- 在对应时间点查看原始贴纸；
- 明确贴纸不进入趋势、相关性或 AI 总结。

### 切片 4：全脸前后变化与阶段趋势

用户能够：

- 一个有效时间点只看到基线；
- 两个有效时间点看到有引用的前后变化；
- 至少三个有效时间点且跨度不少于 7 天时看到阶段趋势；
- 查看引用的时间点、状态事实、信息来源和无法支持的部分；
- 在证据不足、AI 失败或引用校验失败时看到固定降级说明；
- 不看到皮肤分数、连续评分曲线、产品疗效或生活因素关联。

完成切片 1–4 后，核心产品闭环成立，可以进行上线前完整验收。

### 切片 5：公开测试就绪

- 完成照片和 AI 授权、授权撤回、账号数据隔离和数据导出；
- 历程中的照片默认使用遮挡或模糊缩略图，由用户主动查看原图；
- 新导航不暴露旧三视角、旧医学分析、旧趋势和聊天入口；
- 验证幂等提交、上传恢复、异步失败恢复和网关安全边界；
- 覆盖新 API 集成测试、移动端端到端测试、真实设备和真实 AI provider 联调；
- 完成适用市场的隐私、上架和合规专项复核。

只有切片 5 的发布阻断项全部关闭后，才进入公开测试。

### 切片间验收门禁

切片 1 是一个不可拆分验收的前后端闭环。后端接口完成、前端页面完成、仅使用 Mock 跑通，或单项自动化测试通过，都不能单独视为切片 1 完成。

进入切片 2 前，必须同时满足：

- 切片 1 的后端、数据库、异步 AI 和移动端功能全部完成；
- 后端与移动端自动化检查通过，PostgreSQL 持久化和端到端闭环有证据；
- `docs/current_status.md` 已记录实际结果、遗留问题和验收证据；
- 用户明确确认切片 1 验收通过。

门禁通过前，不生成或执行 Slice 2 的 ACTIVE 详细计划，不开发产品记录业务。产品页可以保留诚实的空状态，但不得以占位或 Mock 冒充 Slice 2 实现。

## 9. 后续扩展，不属于当前 MVP

### 后续切片 6：观察范围选择与六个固定区域

增加互斥选项“全脸”与“选择区域”。区域模式使用固定区域 ID，创建多个 `region` 观察目标，并让每个目标拥有独立处理状态。全脸记录继续作为全脸历史存在。

### 后续切片 7：区域事件与区域时间点

为每个区域建立独立事件和时间点，定义一个当前事件、30 天续接、主动结束和重新开始规则。`full_face` 不进入区域事件。

### 后续切片 8：区域趋势

只比较同一区域的有效时间点，生成与全脸趋势分离的区域前后变化和阶段趋势。历史原图可以在用户授权下重新处理，但旧全脸摘要不能直接当作区域证据。

后续能力只有在全脸 MVP 的用户数据证明有价值时才排期。

## 10. AI 与安全边界

AI 可以：

- 描述当前照片可见的主要位置、近似数量或范围、分布、覆盖和日常外观；
- 对有效全脸时间点做有引用的前后变化和阶段趋势；
- 明确无法判断的内容。

AI 不可以：

- 诊断疾病或使用医学皮损分类；
- 输出严重度、皮肤健康指数、改善分或风险分；
- 推荐产品、药物、剂量、频次、疗程或就医方案；
- 根据未记录内容补齐事实；
- 把产品使用或生活背景解释为原因、相关因素或疗效；
- 修改用户原图或覆盖用户原文；
- 引用不存在、属于其他用户或不满足门槛的记录。

AI 调用必须经过统一 gateway。超时、重试、退避、熔断、结构校验和最终失败由 gateway 负责，产品业务层只消费稳定状态和通过校验的结果。

## 11. 视觉与文案基线

新页面采用语义化颜色 token，基准色为：

| 语义 | 色值 | 用途 |
|---|---|---|
| 品牌鸢尾紫 | `#8F85CE` | 品牌识别和非正文强调 |
| 主操作紫 | `#6F63B7` | 主要按钮和关键交互 |
| 淡薰衣草 | `#F2EFF8` | 柔和状态背景 |
| 薄荷绿 | `#C5DCCC` | 中性辅助状态 |
| 杏仁黄 | `#ECD083` | 提醒和上下文 |
| 深暖灰 | `#5A5651` | 主要文字 |
| 暖白 | `#FFFDF8` | 页面背景 |

品牌鸢尾紫不作为小字号正文色。颜色不承担“改善/恶化”的唯一表达，也不把皮肤状态渲染成红绿输赢。

文案使用“记录、观察、可见、无法判断、信息不足”等中性表达，避免“检测、诊断、严重、治愈、有效、无效”等可能造成医学或疗效暗示的词。

## 12. 验收标准

### 12.1 功能闭环

- 原图或用户原文在显示成功前已经可靠保存；
- 同一幂等请求不会生成两条观察记录或两个 AI 任务；
- 当前 MVP 自动保存 `full_face`，页面没有伪造的单选范围步骤；
- 用户离开并重启应用后仍能读取记录和 AI 状态；
- AI 最终失败不会丢失原始记录，用户可以用文字完成；
- 用户可以多选个人产品、录入新产品或使用“未注明产品”；
- 生活背景可以全部跳过，并且不会进入趋势输入；
- 1/2/3 个有效时间点分别遵守基线、前后变化和 7 天阶段趋势门槛；
- 所有变化结论能回溯到真实时间点、事实和来源；
- 新四栏导航不暴露 legacy 主流程。

### 12.2 用户理解

测试需要确认用户能够理解：

- 全脸分析是照片可见状态整理，不是诊断或评分；
- 数量是条件允许时的估算，不是医学计数；
- 产品使用和生活背景只是同时段事实，不代表关联或疗效；
- AI 失败不等于记录失败；
- 历史全脸结论以后不会被自动当作区域结论。

### 12.3 发布阻断

以下问题存在时不能进入公开测试：

- 页面提示保存成功后原始记录仍可能丢失；
- 用户可以访问其他账号的照片、记录或产品；
- 原图被生成式修改或被派生文件覆盖；
- 无照片或 AI 失败时无法完成观察；
- 产品层绕过 gateway 直接管理模型调用；
- 页面输出诊断、严重度、皮肤分数、治疗或产品建议；
- 趋势引用不存在或不属于当前用户的事实；
- 产品使用或生活背景进入趋势方向计算；
- 旧三视角仍是新记录的必填流程；
- 新版 API 缺少集成测试，或移动端没有真实后端端到端验证；
- 未完成真实设备、真实 provider、隐私和目标市场上架合规复核。

## 13. 与现有实现的关系

优先复用：认证、协议、账号隔离、对象存储、签名 URL、请求幂等模式、通用 AI provider gateway、Expo 工程、Token 安全存储、基础组件和相机权限封装。

不能直接沿用为新业务事实：旧 CheckIn、三视角聚合、拍照质量门槛、医学化 Analysis Schema、严重度、皮肤指数、Patch lineage、旧趋势、聊天和旧日记。

新记录模型与旧 CheckIn 分离。历史迁移和旧数据暂时保留，新导航隐藏 legacy 入口。旧数据不能伪装成满足全脸新 Schema 或未来区域规则的证据。

本文件不绑定路由名称、数据库表名或具体类名。它们由经用户批准的 ACTIVE 实施计划定义。

## 14. 变更规则

新增能力进入 MVP 前必须回答：

1. 它是否直接帮助验证“全脸观察—AI 整理—实际产品使用—后续回看”的闭环；
2. 删除它是否会导致核心产品判断无法验证；
3. 它是否增加新的权限、领域实体、一级页面或 AI 结论；
4. 团队能否在当前切片内实现并验证。

第二项为“否”且第三项为“是”时，默认移入后续版本。任何区域能力都按第 9 节处理，不得静默回到当前 MVP。

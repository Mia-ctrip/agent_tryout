# Skin Care Agent 全局 UI 重构执行总览

## 目标

在不改变产品业务语义和数据闭环的前提下，把现有移动端统一为“柔和自然的私人皮肤档案”，并以四组金标准页面建立可持续的视觉基线。

## 架构策略

本轮采用“令牌 → 共享组件 → 页面模式 → 业务页面”的迁移顺序。先建立可复用基础，再逐组迁移页面，避免每个页面独立设计。现有 reducer、API、领域模型、路由与持久化逻辑默认保留；只有当视觉实现暴露真实接口缺口时才记录缺口，不用演示数据补齐。

## 四阶段

| 阶段 | 范围 | 主要验收 |
|---|---|---|
| 1 | 基础系统、观察首页、拍摄、确认、观察结果 | 从首页到保存观察的连续旅程统一且可恢复 |
| 2 | 历程首页、面部分区、区域时间线、当天证据 | 真实左右、真实照片、非因果边界均保留 |
| 3 | 产品首页、产品详情、药膏使用记录 | 真实包装可辨认，不像电商货架，不做推荐 |
| 4 | 我的、登录注册、协议、表单、系统状态、全局审计 | 所有页面风格稳定，表单与错误页无装饰，完成回归 |

## 阶段门禁

每阶段必须同时满足：

1. 新增或更新的契约测试先失败后通过。
2. 受影响的既有业务测试保持通过。
3. `npm run typecheck` 和 `npm run lint` 通过。
4. 关键页面在目标手机视口无横向溢出、遮挡或键盘问题。
5. 用户验收关键截图或真机渲染。
6. `docs/current_status.md` 只在获得用户授权并有验证证据后更新。

## 不在本计划内

- 后端 schema、API 或 AI prompt 重构。
- 产品推荐、疗效判断、因果分析和医学诊断。
- Slice 6 趋势能力补做。
- 产品归档后端接口。
- 未获得权利确认的品牌摄影素材上线。

======================================================================
提示词 1：第一次生成完整手机 Web 原型
======================================================================

请生成一个可点击、可演示的中文手机 Web 高保真原型。

不要生成官网、落地页、后台 Dashboard 或原生 React Native 项目。请生成一个在 v0 Preview 中运行的移动端 Web App，用于验证真实产品流程，后续会根据原型在 React Native + Expo 中重新实现。

请不要先解释方案，直接完成整个可运行原型。

一、技术要求

使用：
- Next.js App Router
- React
- TypeScript
- Tailwind CSS
- shadcn/ui
- Phosphor Icons，同一项目不要混用其他图标库

限制：
- 仅使用本地 mock 数据
- 不连接数据库
- 不连接后端 API
- 不实现登录注册
- 不实现真实 AI
- 不申请真实相机权限
- 不上传或保存任何真实照片
- 不增加电商、社区、内容流、聊天或问答
- 控制依赖数量，确保 v0 Preview 可以直接运行
- 所有主要按钮和底部导航必须可以点击
- 使用 router 或本地状态串联完整流程
- 刷新页面后仍能从默认演示状态开始
- 桌面预览时，将 App 居中显示在约 390px 宽的手机容器内
- 手机屏幕上使用完整宽度和 min-height: 100dvh
- 处理底部安全区，固定底部导航不能遮挡内容

二、产品定位

这是一个面向痘肌用户的长期皮肤管理伴侣。

产品通过：
1. 当前照片或用户主动记录
2. 用户最关注的面部区域
3. 实际使用过的外用产品
4. 后续皮肤状态和个人感受

帮助用户逐渐理解：

“当时是什么状态，实际使用了什么，后来发生了什么。”

产品核心不是单次 AI 测肤，而是同一区域跨时间的变化记录，以及基于个人历史形成的产品反应记忆。

首页主标题必须使用：

“看见变化，也看懂变化。”

副标题必须使用：

“基于真实照片与使用记录，呈现可追溯的个人皮肤变化趋势。”

不要在首页突出 AI。AI 只是隐藏在记录整理、比较和归纳背后的能力。

三、体验原则

整个产品必须遵守：

- 不评价用户皮肤好坏
- 不使用皮肤分数、健康分、严重度或百分制
- 不诊断疾病或病因
- 不输出医学皮损分类
- 不推荐用户应该使用什么产品
- 不提供剂量、频次、疗程、停用、更换或组合建议
- 不把使用产品后的变化表达为疗效或因果
- 不使用“有效”“治好了”“适合你”“建议继续使用”等表达
- 不使用连续打卡、断签、任务进度、红点和焦虑提醒
- 不用红色和绿色表达皮肤变好或变差
- 未记录不等于没有发生
- 没有后续记录不等于痊愈或恶化
- 照片质量不足只限制照片比较，不让整条记录失效
- 用户可以不拍照片，直接记录当前状态
- 用户输入与照片分析是同等有效的信息来源
- 原始照片默认遮盖，只有用户主动点击后才显示演示图片
- 不使用真实医疗照片或令人不适的皮肤特写

页面文案应自然、克制、温和、清楚，避免营销腔、医生口吻和 AI 腔。

可以使用的表达示例：

- “这次记录已保存”
- “这张照片可以作为后续比较的起点”
- “拍摄条件不同，这次暂不进行照片对比”
- “你补充的当前状态仍会进入个人趋势”
- “最近的记录变化混合：泛红范围较小，但仍有新的可见变化”
- “这表示个人历史中的时间关联，不代表产品疗效”
- “今天只记录到这里也可以”
- “当前记录还不足”

四、信息架构

底部固定四个一级导航：

1. 观察
2. 历程
3. 产品
4. 我的

使用图标加文字。当前选中项使用品牌紫色。

不要增加独立的 AI、聊天或问答入口。

五、核心演示场景

请预置两个演示阶段：

A. 第一次使用
用户还没有任何历史记录。完成第一次记录后，只生成当前事实卡片，不生成趋势、相似历史或产品规律。

B. 已有个人历史
用户已经有同一区域的多个时间点和三段独立产品使用记录，可以展示事件趋势和个人产品反应记忆。

在“我的”页面底部提供一个低强调的“切换演示状态”区域，让测试人员可以在“第一次使用”和“已有个人历史”之间切换。它只是原型测试工具，不要放在主要产品入口中。

六、页面与交互

请实现以下页面和完整跳转。

页面 1：观察首页

首次使用状态：

顶部显示简洁文字品牌“Skin Care”，不要设计复杂 Logo。

显示主标题：
“看见变化，也看懂变化。”

显示副标题：
“基于真实照片与使用记录，呈现可追溯的个人皮肤变化趋势。”

首页采用不对称双节奏层级。

第一层是面积较大的“记录皮肤变化”主卡：
- 使用淡薰衣草背景
- 有一个简洁的相机图标
- 说明“用一张照片或简单记录，留下这次值得关注的变化”
- 唯一主要 CTA：“记录现在的变化”
- 点击后进入模拟拍摄页
- 卡片底部提供两个低强调次级操作：
  - “记录刚刚使用”
  - “做一次完整记录”
- “做一次完整记录”点击后弹出说明：“完整记录会引导你拍摄多个角度，只在你主动需要时使用。”本原型不继续实现多角度流程

第二层是视觉更轻的“今天的生活背景”卡：
- 说明它是可选记录
- 提供贴纸式选项：睡眠不足、压力较大、经期、饮食变化、情绪波动、护理变化
- 提供“今天没有特别变化”
- 选择后收拢显示已选择的内容
- 不显示完成率、连续天数或未完成状态

已有历史状态下：
- 保持相同首页层级
- 不自动展示历史脸部照片
- 如果用户主动设置了观察提醒，可以显示一句低强调提示：“你选择在今天回看下巴这段变化”
- 不使用催促语气

页面 2：模拟拍摄页

使用沉浸式深色相机界面，但保持克制。

显示：
- 一个安全、普通的中性人像演示图，作为模拟取景画面
- 不使用皮肤疾病特写
- 面部轮廓参考
- 提示“保持光线均匀”
- 提示“让关注区域清晰可见”
- 大型圆形拍摄按钮
- 返回按钮
- 低强调文字按钮：“暂时不拍，直接记录”

点击拍摄按钮后：
1. 短暂显示与页面结构一致的处理状态，不使用无限旋转图标
2. 进入“确认关注位置”页面

点击“暂时不拍，直接记录”后：
1. 进入无照片记录页面
2. 不要返回首页
3. 它仍然属于同一个“记录现在的变化”流程

页面 3：确认关注位置

展示刚才的演示照片。

标题：
“这次你最关注哪里？”

说明：
“点一下照片中的位置即可，我们会以你的关注为准。”

允许用户点击下巴、左脸颊、右脸颊或额头区域。

点击后：
- 使用一个克制的紫色圆形标记显示选中位置
- 下方显示系统建议区域，例如“建议区域：下巴”
- 用户可以修改区域
- 不要求填写医学名称
- 主要按钮：“确认这个位置”

页面底部提供一个低强调的演示入口：
“模拟照片条件不足”

点击后显示质量提示：
- 标题：“这张照片暂时不适合连续比较”
- 内容：“光线偏暗，但你仍然可以保存这次记录，并补充当前状态。”
- 操作：“重新拍摄”和“继续记录”
- 不将照片标记为失败
- 不使用红色警告样式

页面 4：无照片或照片信息不足时的状态补充

标题：
“现在这个区域是什么感觉？”

区域选择：
- 下巴
- 左脸颊
- 右脸颊
- 额头
- 鼻周
- 暂时不确定

当前状态使用固定选项，不要求长文本：
- 泛红范围比之前小
- 泛红范围比之前大
- 表面看起来更平整
- 出现新的可见变化
- 整体基本稳定
- 变化比较混合
- 目前说不清

可选个人感受：
- 刺痛
- 发痒
- 紧绷
- 没有特别感受
- 暂时不记录

底部说明：
“没有照片也可以形成一条完整记录，并进入同一条个人趋势。”

主要按钮：
“保存这次记录”

页面 5：这次变化卡

保存后生成独立成立的“这次变化卡”。

顶部先显示：
“这次记录已保存”

卡片包含：
- 记录时间：今天 21:30
- 主要区域：下巴
- 关注位置：下巴右侧
- 照片依据状态：“可作为后续比较起点”或“本次主要依据你的记录”
- 中性状态标签，不使用好坏颜色

卡片严格按照四个区块组织：

1. 我注意到的
示例：“你最关注下巴右侧，并记录了局部泛红。”

2. 照片留下的事实
有可用照片时：
“照片保留了当前区域的可见状态，可以作为后续比较的个人起点。”

无照片时：
“这次没有照片依据。”

照片条件不足时：
“照片已保存，但拍摄条件暂不支持连续照片比较。”

3. 目前知道的
示例：“当前记录来自照片和你的补充。”

4. 目前还不知道的
示例：“现在还没有足够历史判断这段变化的方向，也没有产品使用记录。”

不要显示皮肤分数、严重程度、改善百分比、产品建议或伪造规律。

底部主要按钮：
“完成”

次级操作：
- “记录刚刚使用”
- “设置观察提醒”

记录刚刚使用应打开产品使用底部弹层。
提醒弹层提供：
- 明天
- 3 天后
- 7 天后
- 自定义
- 不提醒

不要设置默认提醒。

页面 6：记录刚刚使用

以底部弹层或独立页面呈现。

标题：
“记录刚刚使用”

说明：
“只记录已经发生的使用。”

预置个人产品：
- 壬二酸凝胶 15%
- 温和洁面乳
- 修护保湿霜

允许多选，组合使用必须作为一个组合记录保存。

字段：
- 使用时间，默认“刚刚”
- 使用区域，可选，可跳过
- 个人备注，可选

主要按钮：
“保存使用记录”

保存后显示：
“使用记录已保存。时间上的先后不会被直接解释为产品效果。”

即使没有活跃变化事件，也允许保存。不自动新建事件，不自动建立因果关系。

页面 7：历程

不要做无限折线图、皮肤评分 Dashboard 或打卡日历。

顶部标题：
“我的历程”

以区域变化事件为主要列表单位。

预置事件：
- “下巴这段变化”
- 开始于 7 月 28 日
- 3 个时间点
- 状态：“正在观察”
- 照片默认使用不透明的“照片已遮盖”封面
- 摘要：“最近的记录变化混合：泛红范围较小，但仍有新的可见变化。”
- 依据标签：“照片与用户记录共同支持”

另一个事件：
- “左脸颊这段变化”
- 状态：“暂停追踪”
- 文案说明暂停追踪只表示近期没有新增记录，不代表已经结束或痊愈

点击“下巴这段变化”进入事件详情。

页面 8：变化事件详情

页面采用摘要优先结构，不要先展示大图或时间轴。

顶部：
- 标题：“下巴这段变化”
- 开始日期：“开始于 7 月 28 日”
- 中性状态：“正在观察”

第一部分：个人结论
“最近的记录变化混合：泛红范围较小，但仍有新的可见变化。”

第二部分：为什么这样判断
- 共有 3 个有效时间点
- 时间跨度 15 天
- 其中 2 次照片具备比较条件
- 泛红范围比第一次记录小
- 最近一次记录中仍出现新的可见变化
- 标注依据：“照片与用户记录共同支持”

第三部分：这次有多大参考价值
- 相似点：“区域和主要状态维度一致”
- 不同点：“第二次记录同时使用了两种产品”
- 未知信息：“有一次生活背景没有记录”
- 不显示置信度百分比或相似度分数

第四部分：下一步可以做什么
只显示非治疗型建议：
- “下次记录时，可以优先保持相近的角度和光线”
- “如果你准备咨询医生或药师，可以带上这段记录”
- 不建议用户开始、继续、停止或更换任何产品

第五部分：“这段时间发生了什么”
使用简洁的纵向时间节点：
- 7 月 28 日：建立个人比较起点
- 8 月 4 日：记录实际使用壬二酸凝胶 15%
- 8 月 12 日：泛红范围较小，同时记录到新的可见变化

照片默认遮盖。点击“查看照片依据”后先弹出确认：
“照片可能让你重新看到当时的皮肤状态，是否继续查看？”
用户确认后才显示中性演示图片。

底部操作：
- “记录现在的变化”
- “补充实际使用”
- “修改观察提醒”
- “停止继续记录”

页面 9：产品

标题：
“我的产品”

包含：
- 搜索产品输入框
- “添加产品”按钮
- 个人外用产品柜
- 不显示产品排行榜、推荐榜或购买链接

产品卡片示例：

壬二酸凝胶 15%
证据状态：“形成个人规律”
事件数量：“3 段独立记录”
主要区域：“下巴、左脸颊”
摘要：
“你记录过 3 段使用后的变化，其中 2 段随后整体缓和，1 段变化混合。”

紧接说明：
“这表示个人历史中的时间关联，不代表产品疗效或适合度。”

不要放“再次使用”“立即购买”“推荐”按钮。

点击卡片进入产品详情。

页面 10：产品详情

标题：
“壬二酸凝胶 15%”

按照四段式决策支持组织：

1. 个人结论
“在你的 3 段独立记录中，使用后较常出现整体缓和的后续记录，同时也有一次变化混合。”

2. 为什么这样判断
- 3 段实际使用记录
- 2 段随后整体缓和
- 1 段变化混合
- 主要涉及下巴和左脸颊
- 依据来自照片与用户记录

3. 这次有多大参考价值
- 相似之处：主要区域和使用方式接近
- 不同之处：其中一次同时使用了修护保湿霜
- 未知因素：一次记录缺少完整生活背景
- 用户曾记录过一次轻微刺痛
- 明确说明不能判断刺痛由该产品导致

4. 下一步可以做什么
- “可以回顾其中一次组合使用的记录，避免把结果归到单个产品”
- “如果准备咨询医生或药师，可以重点说明一次刺痛和一次组合使用”
- 不提供任何具体使用建议

底部可以提供：
- “查看相关事件”
- “补充个人备注”
- “纠正产品信息”

不要提供“继续使用”“适合你”“购买”或类似操作。

页面 11：我的

使用简单分组列表，不做设置 Dashboard。

分组：
- 我的记录方式
  - 观察提醒
  - 完整记录偏好
- 照片与隐私
  - 照片预览
  - AI 分析授权
  - 应用锁
  - 存储与删除
- 数据与账号
  - 导出我的记录
  - 删除数据
  - 账号与安全
- 关于与支持
  - 产品能力边界
  - 医疗免责说明
  - 隐私说明
  - 意见反馈

在页面最底部加入“原型演示设置”：
- 第一次使用
- 已有个人历史
- AI 暂时不可用
- 照片条件不足

“AI 暂时不可用”状态下仍能完成无照片记录或用户状态记录，不能阻塞保存。

七、视觉系统

整体方向：

“现代温暖底座 + 局部手账语法”

内部视觉原则：

“轻松地记录，认真地对待证据。”

品牌、导航、主要流程：
- 清晰
- 现代
- 温暖
- 有呼吸感
- 克制可信

生活背景和轻互动：
- 可以少量使用贴纸感
- 不能压过核心记录
- 不要变成儿童手账或日记 App

证据、照片、趋势、产品反应记忆、隐私和删除：
- 保持克制
- 排版清楚
- 不使用倾斜卡片、胶带或大量装饰

固定颜色：

- 品牌紫鸢尾：#8F85CE
- 淡薰衣草：#F2EFF8
- 清新薄荷：#C5DCCC
- 杏金：#ECD083
- 主文字深暖灰：#5A5651
- 页面暖白背景：#FFFDF8
- 主要 CTA 深紫：#6F63B7
- 白色：#FFFFFF
- 边框使用低对比暖灰紫

色彩规则：

- 主 CTA 使用 #6F63B7，文字为白色，保证 WCAG AA 对比度
- #8F85CE 只用于品牌、选中状态、关键图标和少量装饰
- 不要大面积使用浅紫背景承载白色文字

八、必须包含的状态

关键流程不能只显示成功状态，还要包含：

- 照片处理中
- 保存处理中
- 保存失败，可重新尝试
- 照片条件不足，但允许继续
- AI 暂时不可用，但允许用户完成基础记录
- 第一次使用，没有历史
- 有历史，能够生成趋势
- 原始照片默认遮盖
- 用户主动确认后查看照片

保存失败、仍在处理和保存成功必须是三种清楚不同的状态。

九、验收要求

9. 是否完全没有皮肤评分、严重度、产品推荐和治疗建议
10. 是否没有独立 AI 或聊天入口
11. 照片是否默认遮盖

16. 所有主要按钮、导航、弹层和状态切换是否真实可操作
17. 所有中文文案是否自然、简洁，没有英文占位符、乱码或无意义内容

如果实现范围过大，优先保证以下核心链路完整可用：

不要为了完成外围页面而牺牲这条链路。

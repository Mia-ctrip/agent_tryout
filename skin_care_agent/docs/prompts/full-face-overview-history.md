## 2. 核心语义

| 名称 | 本任务含义 |
|---|---|
| 选区中的“全脸” | 用户主动选中固定六区的快捷操作 |
| 全脸结果概览 | 完整原图，加上当次已选区域已有的事实与状态 |
| 历程“全脸” | 按观察记录发生时间浏览完整照片，包含只选部分区域的记录 |
| 历程“分区” | 原有六区图、区域事件、时间点与局部详情 |
| 旧 `scope_type = full_face` | 只读兼容的历史目标类型，不是新全脸功能的数据类型 |

**新记录仍只有 1–6 个 `region` 目标。“全脸”不创建新类型、综合分析任务、独立事件或重复观察。** 用户看到的整体概览来自现有区域结果，不再调用模型写一段全脸结论，不汇总成总数量、严重度或评分。

## 3. 选区交互

1. 在既有六区选择界面增加“全脸”快捷操作，说明“选择全部 6 个区域”。它独立于六个解剖区域，不画成第七块区域。
2. 点击后选中现有字典全部六区：`forehead`、`left_face`、`right_face`、`nose_area`、`mouth_area`、`chin`。
3. 全选后仍可逐区取消；取消任一区域后，全脸不再显示已全选。逐个选满六区与快捷操作的结果完全相同。
4. 重复点击已全选的操作不清空、不重复添加、不创建任务。全选状态由实际六区集合推导，不增加业务字段记录“全脸模式”。
5. 不自动默认全选，不由 AI 推荐选区；保存前仍须用户确认，按钮显示实际数量，如“确认 6 个区域”。零选区不能提交。
6. 照片区域图、文字选项、全脸状态、确认数量同步，保留用户本人真实左右。
7. 六个目标沿用既有异步处理和区域事件归属；多个区域达到 30 天门槛仍使用现有汇总确认，不新增全脸事件。
8. “全脸”仅指上述六区，不扩展眼周、头皮、颈部或身体部位；看不清的区域按原契约说明无法判断。

## 4. 当次结果概览

- 全选六区时，默认展示全脸概览：一张完整原图、明确的当次观察范围，以及六区简洁小结/状态列表；点击某区进入既有详细结果。不要在默认页面堆叠六份完整报告。
- 只选 1–5 区时，保留原分区结果默认，但可查看完整照片概览；概览只展示当次所选区，标注“本次观察：下巴”等范围，不把未选区显示为正常、失败或待分析。
- 从历程“全脸”打开观察时优先展示概览。切换概览/分区仅改变视图，不修改原始选区、不补选、不触发 AI。
- 每区独立显示 `queued/processing/completed/needs_input` 等真实状态；已有有效结果先展示，失败区域可以重试或补充文字。不能以“所有目标完成”为前提隐藏整张原图或所有已完成区域。
- 区域 AI 小结保持原始来源；用户文字标为“你的记录”。显示照片局限，不将文字伪装成照片分析。
- 不拼接生成新的综合结论，不另加模型请求，不对六区数量求和、对比或推断整体严重程度。
- 完整原图展示保留项目隐私规则、原图访问、加载/错误/补签能力；概览不使用局部裁图冒充完整照片，也不修改存储原图。
- 保留正在落地的“照片保存 → 产品使用步骤（AI 后台处理）→ 观察详情”顺序。AI 完成或六区概览就绪不能抢走产品选择页面，不能重新弹出使用询问。

## 5. 历程双视图

### 入口与组织

- 在区域图上方放“全脸 / 分区”切换。首次进入保留分区默认；切换和详情返回时保留所选视图与浏览位置。
- 分区视图沿用现有六区图、当前/历史事件、有效时间点及局部原图取景。
- 全脸视图使用观察记录数据，按记录发生时间从近到远浏览有照片记录。展示完整照片预览、日期/时间、实际选区及处理状态，点击进入同一观察概览。
- 只选下巴等部分区域的照片也在全脸视图出现，不把“全脸列表”实现为仅筛选六区全选，更不能筛选旧 `scope_type = full_face`。

### 去重、时间与状态

- 按 `observation_id` 去重：六个目标/六个事件仍是一条照片记录。
- 同一天多次观察全部保留，不按日期、图片文件或图片哈希去重。记录发生时间与展示时区沿用现有语义，同时间记录使用稳定次序。
- 列表只读引用原记录，不复制照片或生成全脸专用记录/事件。
- 已保存有照片即可回看，不依赖有效区域事件。AI 全部处理中、全部失败、部分完成都要展示真实状态。
- 全脸与分区分别计算空态。只有照片尚无有效区域时间点时，全脸有内容，不能提示整个历程为空。
- 正确读取分页数据，不能只取区域事件或默认第一页后静默遗漏照片。已加载记录发生刷新/重叠页时不重复展示。
- 照片加载失败、签名过期或补签中保留记录及恢复入口，不因暂时取不到图而丢弃记录。

### 历史与其他事实

- 旧 `full_face` 有照片记录明确标注为历史全脸记录，沿用旧版本展示；不能拆成六区、自动重新分析或混入新的六区 AI 事实。
- 已有无照片历史不进入照片列表，但保留原有原文、来源和可达入口，不删除、不补造照片。
- 产品使用和生活背景保留独立时间上下文；不重复复制为六区分析证据，不在本任务中增加关联或因果结论。
- 新版区域照片即使展示在“全脸”，也不得调用旧全脸分析、对比或趋势接口。既有 Slice 6 与后续区域趋势不属于本任务。

## 7. 验收清单

1. 全脸一次选中六区；重复点击不重复，逐区取消、手动选满和全选状态一致；确认数量及左右方向正确。
2. 保存只产生一个观察和六个 `region` 目标，没有第七目标、新 `full_face`、全脸事件或额外综合 AI 请求。产品使用流程继续正常。
3. 六区全选默认概览；只选 1–5 区时范围清楚；从全脸历程进入部分选区记录仍显示完整照片与实际选区事实。
4. 六区全成功、部分成功部分处理中、部分失败、全部失败及文字补充都有真实展示；已完成区可读、失败区可恢复，不伪造或隐藏范围。
5. 切换概览/分区以及反复回看不触发 AI、不改变区域归属，也不重复产品询问。
6. 同一记录关联六个事件仍只显示一条全脸照片；同一天两次记录显示两条；相同图片用于两次独立观察也保留两条；分页重叠不重复。
7. 有照片但无有效区域时间点时全脸可见；全脸与分区各自空态正确，加载/错误/签名补签不误删记录。
8. 列表按发生时间排序，时区显示正确；切换、进入详情、系统返回保留对应视图和位置，新增记录刷新可见。
9. 新区域照片、旧 `full_face` 照片与无照片历史混合时来源和入口正确，不改写数据，不调用旧趋势。
10. 小屏、长文本、大字体、读屏、横竖滚动与返回可用；真实后端回看与跨账号隔离成立。

运行与改动匹配的行为测试，不以源码字符串检查代替交互验证。至少运行 `mobile` 的 `npm run test:unit`、`npm run typecheck`、`npm run lint`，以及本次 diff 的 `git diff --check`。后端如改动，运行对应 pytest/Ruff；涉及真实持久化时在明确可丢弃的 PostgreSQL 环境验证。

使用可用 Android 设备/模拟器走全选、保存、产品步骤、概览、分区和历程返回。Web 可补充布局验证，但不能代替原生手势/返回与真实后端闭环。隔离样例明确标注，缺少环境的验收如实列为未执行，不伪报完成。

# Slice 4A：标准产品目录、搜索与图片设计

> 状态：APPROVED
>
> 日期：2026-08-24
>
> 依据：用户已逐段确认产品粒度、双层引用、图片、离线导入、搜索、监管资料、移动端交互及验收边界，并于 2026-08-24 完成书面规格确认。

## 1. 背景与目标

现有 Slice 4 已实现个人产品柜、手动名称、多产品使用和“未注明产品”，但没有平台标准产品目录、产品图片或搜索匹配。用户已确认扩大当前 MVP 范围，新增 Slice 4A，在不破坏既有个人产品和使用历史的前提下提供：

- 配方版本级的标准产品身份；
- 标准产品图片和用户自建产品图片；
- 中英文名称、别名、拼音别名和模糊匹配；
- 从标准目录一键加入个人产品柜并立即用于多选；
- 普通护肤品、药品和医疗器械的监管类别；
- 有来源、有版本、可追溯的官方说明书【适应症】原文。

标准目录只降低产品录入成本并保存原始资料，不提供产品推荐、疗效判断、用药建议或产品与皮肤变化的相关性、因果解释。

## 2. 已确认的产品决策

1. 标准产品采用“配方版本级”身份：品牌、正式产品名、产品类别和配方版本共同决定产品语义。浓度、型号或正式版本代表不同配方时拆为不同产品；容量、包装、渠道不同但配方相同时不拆分。
2. 采用双层引用：平台维护 `StandardProduct`，用户柜中的 `PersonalProduct` 可引用一个标准产品；产品使用仍只关联个人产品。
3. 标准产品必须有平台维护的一张当前主图；用户自建产品允许保存一张可选图片。
4. 首版使用版本化离线导入包和幂等导入命令，不建设运营后台，不进行自动网页抓取。
5. 搜索先匹配个人柜，再匹配标准名称与别名，最后进行模糊匹配；已加入的标准产品不得重复加入同一用户的产品柜。
6. 标准目录覆盖普通护肤品、药品和医疗器械。药品和医疗器械资料必须保留官方来源和版本；普通护肤品没有官方“适应症”时保持为空，不把宣传文案改写成适应症。
7. 用户自建产品不自动绑定、合并或改写为标准产品；未来只有在用户明确确认后才能建立标准引用。

## 3. 数据模型

### 3.1 StandardProduct

`standard_products` 至少包含：

- `id`：内部稳定 ID；
- `catalog_code`：导入侧稳定且唯一的产品编码；
- `brand_name`：品牌原名；
- `official_name`：正式产品名；
- `product_category`：产品类别；
- `formula_version`：配方、型号或正式版本；
- `key_strength`：用于区分配方的关键浓度，可空；
- `regulatory_type`：`cosmetic | drug | medical_device`；
- `registration_number`：注册或备案编号，可空；
- `market_region`：上市国家或地区；
- `primary_image_asset_id`：当前主图；
- `status`：`active | inactive`；
- `import_batch_id`、创建和更新时间。

启用的标准产品必须有主图。药品和医疗器械必须有可核验的官方资料记录；普通护肤品可以没有【适应症】字段。

### 3.2 StandardProductAlias

`standard_product_aliases` 保存中文名、英文名、简称、常见写法和导入方明确提供的拼音别名。别名归一化后参与搜索，但不替代正式名称，也不自动由 AI 生成。

### 3.3 ProductImageAsset

`product_image_assets` 保存对象存储键、MIME、字节数、宽高、SHA-256、来源类型、创建时间和归档状态。图片二进制不写入 PostgreSQL。图片资产不可原地覆盖；产品换图时创建新资产并切换当前引用，旧资产继续服务历史快照。

标准产品图由平台导入维护。用户自建图按用户隔离保存，只能由所属账号获取签名读取地址。

### 3.4 StandardProductDocument

`standard_product_documents` 至少包含：

- 标准产品 ID；
- 国家或地区、语言、监管类别；
- 说明书版本和生效日期；
- 批准、注册或备案编号；
- 官方来源名称和来源地址；
- `indications_original_text`：【适应症】原文，可空但不得伪造；
- 原始文档对象存储引用，可空；
- 原文或原始文件校验哈希；
- 导入批次、当前有效标记和归档时间。

说明书版本只新增、不覆盖。药品或医疗器械若无法核验官方来源，不得启用对应标准产品。历史产品使用保存当时引用的说明书版本 ID。

### 3.5 PersonalProduct 与历史快照

扩展现有 `personal_products`：

- 新增可空 `standard_product_id`；
- 新增可空的用户显示名称覆盖；
- 新增可空的用户图片资产 ID；
- 保留现有名称字段和现有记录，历史个人产品迁移后均视为用户自建产品。

同一用户最多拥有一条引用同一标准产品的个人产品，使用数据库唯一约束保证并发安全。标准产品更新会改变个人柜的当前标准资料展示；用户自定义显示名保持不变。

扩展 `product_use_products`，保存使用当时的产品显示名称、品牌、配方版本、图片资产 ID 和说明书版本 ID。产品目录后续更新或停用不能改写历史使用展示。

## 4. 导入与数据治理

导入包包含版本清单、产品、别名、图片、说明书资料和对应校验哈希。导入命令支持 `dry-run` 和正式执行，并遵循：

1. 校验稳定编码、产品粒度、别名归属、图片可读性、文件哈希、监管资料来源和引用完整性；
2. 将图片和原始文档写入暂存对象键；
3. 在数据库事务中幂等写入导入批次、目录资料和最终引用；
4. 数据库提交后确认资产可用；失败时回滚数据库，并把未引用暂存资产登记到清理清单；
5. 重复执行同一导入版本不创建重复产品、别名、文档或图片；
6. 产品下架只改为 `inactive`，不删除标准产品、个人柜引用或历史快照。

系统不自动抓取网页。只有来源、授权和使用权明确的图片、说明书与原文才能进入导入包。

## 5. 搜索与去重

搜索由后端执行，移动端输入停止约 250 毫秒后发送请求。搜索排序为：

1. 个人产品柜中的完全匹配；
2. 标准产品正式名称、品牌或别名完全匹配；
3. 前缀匹配；
4. 包含匹配；
5. 拼写相似度匹配。

后端对大小写、全半角、空白和常见标点进行确定性归一化，并使用索引字段与 PostgreSQL trigram 相似度支持模糊匹配。拼音只来自受控别名，不自动推断。统一搜索结果使用 `source_type = personal | standard` 区分来源，排序必须稳定；标准结果还返回是否已加入个人柜及现有 `personal_product_id`。

模糊结果只供用户选择，系统不得自动认定两个产品相同。没有合适结果时提供用户自建入口；近似标准产品存在时应先展示，但不能阻止用户创建自建产品。

## 6. API 契约

- `GET /api/v1/product-search?q=&limit=&cursor=`：统一搜索当前用户的个人产品柜和标准目录；返回来源类型、图片、品牌、正式名称、配方版本、类别、监管类型及个人柜状态。
- `GET /api/v1/catalog/products/{standard_product_id}`：返回标准产品详情、当前主图、当前有效说明书【适应症】原文和来源。
- `POST /api/v1/products/from-standard`：以客户端请求 ID 和标准产品 ID 幂等加入个人柜；已经加入时返回现有个人产品。
- `POST /api/v1/products/custom`：创建用户自建产品，接受名称和可选图片。
- 现有 `GET /api/v1/products`、产品使用、产品详情和产品历史接口继续以个人产品为中心，并增加标准来源、图片和历史快照字段。

所有写接口继续使用认证、账号隔离、客户端 UUID 幂等和 PostgreSQL 事务。用户图片只能由所属用户读取；标准图片和说明书通过受控签名 URL 返回。

## 7. 移动端流程

### 7.1 产品页

- 顶部显示“搜索或添加产品”；未输入时展示个人产品柜，输入时显示分层下拉结果。
- 结果项显示主图、品牌、正式名称、配方版本和监管类型。
- 已在柜中的标准产品显示“已在产品柜”；未加入的显示“加入产品柜”。
- 用户自建产品显示用户图片和“用户自建”标记。
- 标准产品详情展示图片、监管资料和官方说明书【适应症】原文及来源。

### 7.2 记录产品使用

- 个人柜继续支持多选；搜索同时匹配个人柜与标准目录。
- 选择已在柜中的产品时直接勾选。
- 选择未加入的标准产品时，一次完成“加入个人柜并选中”。
- 没有合适结果时进入用户自建流程，名称预填，可拍照或从相册选择一张可选图片；保存后立即选中。
- 用户仍可不选择任何产品，以“未注明产品”完成记录。

适应症原文不进入搜索摘要或选择提示。标准库结果顺序不表示推荐，也不得由皮肤照片、AI 结果或趋势驱动。

## 8. 异常与降级

- 搜索失败时保留已加载的个人柜和用户自建入口，不阻断产品使用记录。
- 标准产品在搜索后停用时，加入请求返回明确业务提示且不创建失效引用。
- 并发重复加入同一标准产品时返回现有个人产品。
- 用户图片上传失败时保留名称和本地图片草稿，允许重试或移除图片后继续。
- 图片签名地址过期时重新获取；图片不可用时展示产品类别占位图，不阻断选择和历史读取。
- 导入批次任何必需资料校验失败时不得部分启用产品。

## 9. 产品与合规边界

- 【适应症】只展示有出处的官方原文，不生成摘要、诊断、推荐、用法用量或疗效判断。
- 药品和医疗器械详情固定提示“请以当前官方说明书及专业人员指导为准”。
- 适应症、产品类别和产品使用记录不得进入 AI 皮肤状态分析、趋势输入或相关性、疗效、因果计算。
- 标准目录不包含推荐、排行榜、社区、电商、导购、包装识别、OCR 或自动相册扫描。
- 普通护肤品没有官方适应症时保持为空；不得把营销功效宣称改写成适应症。

## 10. 迁移与兼容

- 在 `0017_life_contexts` 之后只追加迁移，不修改已有迁移。
- 现有 `personal_products` 全部保留，`standard_product_id` 和用户图片均为空，语义为用户自建产品。
- 现有产品使用关联保持有效；新增快照字段通过现有个人产品资料回填，且回填过程不推断标准产品身份。
- 现有客户端可以继续使用原产品 API；新版客户端逐步切换到标准目录和自建图片接口。
- 不自动把历史个人产品匹配到标准目录，也不跨用户合并数据。

## 11. 验收标准

只有以下条件全部通过，Slice 4A 才算完成：

- 迁移后现有个人产品、产品使用和产品历史数量及归属不变；
- 导入 `dry-run`、重复导入、失败回滚、停用和版本更新均通过自动化测试；
- 搜索覆盖中文、英文、别名、拼音别名、前缀、包含、模糊匹配和稳定排序；
- 同一用户不能重复加入同一个标准产品，并发请求仍返回同一个人产品；
- 标准产品与用户自建产品均可进入同一次多产品使用记录；
- 标准主图更新后个人柜展示新图，历史使用仍展示原图片快照；
- 说明书新旧版本均可追溯，历史使用引用保存时的说明书版本；
- 用户自建图片通过账号隔离、类型、尺寸、大小和文件可读校验；
- 搜索失败、图片失败和标准产品停用均有明确降级，不阻断“未注明产品”或用户自建流程；
- 后端单元测试、PostgreSQL 集成、导入脚本、API 闭环、移动端单元测试、静态检查和 Android 端到端验收通过。

## 12. 切片归属

已完成的 Slice 4 保留为“个人产品柜与实际产品使用”基础闭环。本设计作为新增的 **Slice 4A：标准产品目录、搜索与图片**，在 Slice 4 基础上实施。Slice 4A 完成前，不能把“新版标准产品能力”宣称为已实现；它不恢复产品推荐、疗效或相关性，也不改变 Slice 5 的生活背景与统一历程边界。

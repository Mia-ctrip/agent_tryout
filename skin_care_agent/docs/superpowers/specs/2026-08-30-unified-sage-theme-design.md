# 全前端统一鼠尾草主题设计

> 状态：待用户复核
>
> 日期：2026-08-30

## 目标

将移动端所有可访问路由（含 legacy 页面）统一为当前鼠尾草视觉规范，消除旧紫色主题、同一语义的多套色值和页面级随机硬编码。功能、路由、数据契约、照片内容与交互顺序保持不变。

## 视觉基线

全局以一套语义 token 表达颜色：

| 语义角色 | 色值 | 用途 |
|---|---|---|
| brand / selected | `#9BAD50` | 品牌、已选导航和选中标识 |
| actionPrimary / focus | `#71813C` | 每个视口唯一主操作、焦点 |
| background | `#F8F0DD` | 页面底色、低压力区域 |
| surface / photoSurface | `#FFFDF7` | 卡片、弹层和中性照片空间 |
| surfaceMuted | `#EDF1DF` | 低强调容器 |
| context / highlight | `#E8C76A` | 生活背景与少量提示 |
| textPrimary / iconStrong | `#46502C` | 正文、标题与高对比图标 |
| textSecondary | `#7A8069` | 辅助信息 |
| border | `#DED8C6` | 低对比边界 |
| danger | `#6A3E35` | 错误与破坏性操作 |

错误、禁用、加载和选中状态继续以文案、图标或边界共同表达，不能仅依赖颜色。原始照片与相机预览不添加主题滤镜。

## 架构与迁移方式

1. 将 `mobile/src/constants/theme.ts` 升级为唯一共享主题源，并保持现有 spacing、radii、`maxContentWidth` 导出兼容。
2. 将 `product-theme.ts` 与 `observation-theme.ts` 改为该主题的兼容语义映射，避免大范围页面重命名导致无关行为变化；仅保留观察流程确有需要的相机遮罩与扫描层 token。
3. 逐页替换 `mobile/src/app` 和 `mobile/src/components` 中旧主题导入、旧紫色、亮白底和硬编码色值，使导航、按钮、输入框、卡片、标签、弹层、加载与错误状态全部使用共享语义角色。
4. 同步 Expo 的启动背景与 Web/原生导航容器，避免启动、栈导航与内容页面出现不同的底色。
5. 允许图片、SVG 扫描辅助层和相机遮罩保留必要的透明色，但应从共享 token 或对应语义导出推导，不能重新引入旧紫色或高饱和装饰色。

## 边界与兼容性

- 覆盖四栏主流程、认证、协议、产品、产品使用、观察、区域事件、历史分析、趋势、日记和相关共享组件。
- 不改变路由、页面数据、保存逻辑、状态机、可访问性标签或动画逻辑。
- 不更改产品照片、用户上传照片与相机原图的像素内容。
- 既有 `colors`、`productColors` 和 `observationColors` 的公开键尽量保持兼容，以便迁移期间不改变业务组件接口。

## 验收与验证

- 全局搜索不得遗留旧主题紫色 `#8F85CE`、`#6F63B7`、`#F2EFF8` 或其旧别名。
- 页面与共享组件不再新增无语义的硬编码不透明颜色；仅透明叠层和图像绘制允许受控例外。
- `npm run typecheck`、`npm run lint` 与移动端单元测试通过。
- 用 Expo Web 静态导出检查所有路由可构建；对重点路由做目标视口视觉检查，确认启动页、导航和页面底色连续，主操作为深绿、选中为鼠尾草，文本保持可读。

## 风险控制

主题迁移主要风险是颜色键替换造成样式回归。通过兼容映射、小批次替换、TypeScript、lint、单元测试和路由构建降低风险；视觉验收重点检查旧 legacy 页面、栈头部、输入焦点、禁用/错误状态以及相机和扫描叠层的对比度。

## 项目定位

Skin Care Agent 是面向反复出现痘痘或相关外观变化用户的长期记录工具，包含 iOS / Android 客户端和 FastAPI 后端。

当前 MVP 的核心价值是：用户主动选择自己在意的面部区域，用一张照片或无照片状态留下记录；系统只分析已选区域，并按区域积累可追溯的前后变化和阶段趋势。产品使用与生活背景只作为时间上下文展示，不生成诊断、严重度、皮肤评分、产品推荐、相关性或因果结论。

## 当前 MVP 能力摘要

1. 单次记录允许零张或一张照片，不要求三视角；
2. 用户可以从固定面部区域中选择一个或多个本次关注区域；
3. AI 按已选区域整理估算数量、空间分布、覆盖范围、主要位置和日常外观；
4. 一个有效时间点只建立基线，两个时间点形成前后变化，至少三个有效时间点且跨度不少于 7 天才形成阶段趋势；
5. 实际产品使用和生活背景按真实时间展示，不参与趋势方向计算；
6. 无照片、照片不可比、AI 不可用或用户撤回 AI 授权时，基础记录仍可完成；
7. 用户可以管理、导出和删除自己的照片、记录与账号。

完整范围、交互、证据规则和发布阻断条件只在 `design/product/skin_care_app_mvp_spec.md` 中维护，本文件不复制更多细节。

## 已废弃的早期 MVP 设想

以下内容属于早期方案，不再定义当前开发：

- 每次强制正面、左侧、右侧三视角；
- 闭合粉刺、丘疹、脓疱等医学皮损分类；
- 严重度等级、皮肤指数 0 至 100 和改善分数；
- 日报、周报、月报和连续皮肤分数曲线；
- 单颗痘痘身份与生命周期追踪；
- 开放式 AI 问答；
- 生活因素相关性或个人产品反应模型。

这些能力是否进入长期产品，由长期产品设计和真实用户证据决定，不能自动回到 MVP。

## 合规红线

- 不诊断疾病或病因；
- 不输出医学皮损分类、严重度或医疗风险等级；
- 不推荐用户选择、开始、继续、停止或更换具体产品；
- 不提供剂量、频次、组合或疗程建议；
- 不把产品使用或生活背景与皮肤变化表达为相关性、疗效或因果；
- 不分析或展示用户没有主动选择的面部区域；
- 不修改原始皮肤照片的像素语义；
- AI 不可用不能阻塞基础记录、历史查看和数据控制。

## 技术栈

| 层级 | 选型 |
|---|---|
| 前端 | React Native + Expo SDK 57 |
| 后端 | FastAPI + PostgreSQL + Alembic |

| AI 视觉 | 多模型网关 |
| 图像处理 | MediaPipe + OpenCV + Pillow |
